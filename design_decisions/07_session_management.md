# Session Management

## Decision
Sessions work like Claude's UI — sidebar list of past sessions,
new session button, tab close ends the session.

## Session lifecycle

```
New session clicked
  │
  ▼
session_id created
Context assembled fresh (L1 + L2 always, L3 if needed)
  │
  ▼
Conversation runs
  │
  ▼
Tab closed / user ends session
  │
  ▼
beforeunload fires → POST /session/end
  │
  ▼
LLM writes summary + skill update
Session saved, appears in sidebar
```

## Session document
```json
{
  "session_id": "abc123",
  "user_id": "gopinath",
  "created_at": "2026-05-22T10:00:00",
  "ended_at": "2026-05-22T11:30:00",
  "mode": "topic_session",
  "topic": "graphs",
  "title": "BFS/DFS revision",
  "transcript": [],
  "summary": "...",
  "skill_update": {}
}
```

Title is auto-generated by the LLM at session end — same way Claude names conversations.

## Abrupt close handling (two-phase save)

```
Phase 1 — auto-checkpoint every N turns:
  raw transcript saved to DB
  no LLM call, cheap

Phase 2 — clean session end:
  full LLM summary + skill update written

If clean end never happens:
  next session start detects orphaned transcript
  runs summary generation before new session loads
```

## Past sessions
Read-only in the sidebar. User can review but the mentor
only operates in the current active session.

## Session modes
- Planning mode — "what should I study today?"
- Topic session — "let's do graphs today"
- Doubt resolution — "I have a doubt about IAM"
- Evaluation mode — "give me a mock test on AWS"

Each mode assembles context slightly differently and has
different session end behaviour.
